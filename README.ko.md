# Lantern

> 이 문서는 영어 [README](README.md)를 번역해 요약한 것입니다. 두 문서의 내용이 다를 때에는 영어 원문이 기준입니다.

**Lantern은 숨겨진 가디언들이 잃어버린 Midnight 신원 비밀값을 복구하게 하고, 그 값이 올바른 값임을 증명합니다.**

이 프로젝트는 Midnight 네트워크 위에서 만들었습니다.

## 문제

Midnight에서 컨트랙트가 확인하는 비밀값은 한 기기의 비공개 상태(private state)에만 있습니다. Midnight 보안 가이드도 "You cannot recover a witness secret from the chain"(체인에서 witness 비밀값을 복구할 수는 없다)라고 분명히 말합니다. 지갑 시드는 키를 복구할 뿐, DApp의 비공개 상태는 복구하지 못합니다. 그래서 기기를 잃으면 신원도 잃고, 그 신원에 연결된 자격 증명, DAO 회원 자격, 가명 계정도 함께 잃습니다.

EVM 체인에서 흔한 소셜 리커버리 설계에도 문제가 있습니다. 가디언 주소를 컨트랙트 저장소에 그대로 두기 때문에, 누가 누구의 신원을 복구할 수 있는지, 곧 실제 사람들 사이의 관계가 모두에게 영구히 공개됩니다. Lantern은 이 목록을 공개 기록에 남기지 않습니다.

## 작동 방식, 다섯 단계

1. **등록.** 소유자의 기기가 신원 비밀값과, 그와 별개인 거부권(veto) 비밀값에 대한 커밋먼트(commitment)를 체인에 올리고, 임계값 *t*를 정합니다.
2. **분배.** 신원 비밀값을 Shamir 방식으로 나누어, 가디언마다 조각(share)을 하나씩 체인 밖에서 전달합니다. 체인에는 각 가디언이 Merkle 트리 안의 솔트가 들어간 커밋먼트로만 남기 때문에, 공개 기록만으로는 가디언이 누구인지 알 수 없습니다. 임계값과 가디언 수는 공개됩니다. 가디언을 추가한 뒤에는 소유자의 기기에서 그 가디언의 키트(비밀값, 솔트, 조각)를 지워야 합니다. 남겨 두면 그 기기를 가진 사람이 정족수를 모두 갖게 됩니다.
3. **복구 요청과 승인.** 기기를 잃은 뒤에는 누구나 새 기기의 공개 키로 복구를 열 수 있습니다. 가디언은 새 기기의 지문(fingerprint)을 소유자에게 다른 경로로 직접 확인한 뒤, 영지식 멤버십 증명으로 승인합니다. 승인할 때마다 널리파이어(nullifier)가 기록되고 공개 승인 수가 하나 늘지만, 어느 가디언이 승인했는지는 드러나지 않습니다.
4. **대기, 또는 거부권 행사.** 복구를 연 뒤 72시간 동안은 확정할 수 없습니다. 소유자가 시작하지 않은 복구도 모두 공개적으로 보이며, 어떤 가디언도 갖고 있지 않은 거부권 카드(veto card)로 취소할 수 있습니다.
5. **확정.** 새 기기는 하나의 증명으로 다음을 모두 보입니다. 가디언이 승인한 바로 그 기기라는 것, 정족수가 채워졌다는 것, 72시간이 지났다는 것, 그리고 다시 모은 비밀값이 등록 때의 커밋먼트를 연다는 것입니다. 조작된 조각으로 만든 값은 거부됩니다. 옛 커밋먼트는 폐기되고, 같은 신원 루트(identity root) 아래에서 새 커밋먼트가 뒤를 잇습니다. 신원 루트를 기준으로 판단하는 DApp은 저장한 값을 하나도 바꾸지 않고 새 기기를 받아들이며, 옛 비밀값은 거부합니다. 따로 배포된 DApp은 위원회가 복구 이후의 스냅숏을 봉인한 뒤부터 그렇게 하며, 그 전까지는 옛 비밀값도 받아들입니다.

새 기기에는 지갑이 없어도 됩니다. 스폰서가 DUST 수수료를 대신 내고, 어떤 회로도 수수료를 낸 쪽을 신뢰하지 않습니다.

## Midnight의 기능을 쓰는 방식

- **witness와 원장(ledger)의 분리.** 신원 비밀값과 그 솔트, 거부권 비밀값, 각 가디언의 비밀값과 솔트, Merkle 경로, 새 기기의 임시 비밀값은 모두 witness로서 기기 안에만 남습니다. 비공개 값이 공개로 넘어가는 지점은 모두 `disclose()`로 표시됩니다.
- **`persistentCommit` 열기.** `finalizeRecovery`는 다시 모은 비밀값이 등록 때의 커밋먼트를 여는지 회로 안에서 확인합니다. 그래서 복구는 "충분한 사람이 동의했다"가 아니라 "올바른 값이다"를 증명합니다.
- **`HistoricMerkleTree`와 널리파이어.** 가디언은 과거의 루트에 대해서도 멤버십을 증명할 수 있어 동시에 들어온 승인도 유효하며, 널리파이어 때문에 한 가디언이 같은 복구를 두 번 승인할 수는 없습니다.
- **`Set` 비포함 확인과 증가만 하는 `Counter`.** "현재 소유자"라는 판단은 폐기 목록에 없다는 부정 명제이며, 회로 안에서 확인됩니다. 정족수는 카운터 비교로 판단하므로, 나중에 들어온 승인이 확정 증명을 무효로 만들지 않습니다.
- **블록 시간 경계.** Compact에는 읽을 수 있는 시계가 없으므로, 두 개의 블록 시간 조건으로 72시간 잠금을 강제합니다.
- **회로 안의 Jubjub Schnorr 서명.** 따로 배포된 DApp을 위해 위원회가 서명한 스냅숏을 회로 안에서 검증합니다.
- **DUST 스폰서.** 새 기기는 지갑 없이 일회용 키로 증명하고, 스폰서가 DUST를 더해 트랜잭션을 보냅니다.

## 직접 확인하는 방법

설치 없이 브라우저에서:

- [데모](https://lantern-midnight.vercel.app/demo): 컴파일된 컨트랙트가 브라우저 안에서 복구 과정을 실행합니다. [직접 공격해 볼 수도 있습니다](https://lantern-midnight.vercel.app/demo#break).
- [Preprod에서](https://lantern-midnight.vercel.app/live): 수정 없이 배포한 컨트랙트의 복구 상태(확정 가능 시각인 2026년 9월 27일 15:03 UTC까지의 카운트다운, 그 뒤에는 확정 여부), 기록된 모든 트랜잭션이 기록된 블록에 있는지 브라우저에서 확인하는 기능, 그리고 신원 하나를 지켜보다가 탭이 열려 있는 동안 새 복구를 알려 주는 기능이 있습니다. 탭 없이 지켜보려면 저장소에서 `LANTERN_NETWORK=preprod npm run watch -- --id <커밋먼트>`를 실행합니다. Node 24와 compact 0.31.1이 필요합니다.
- [복구 연습](https://lantern-midnight.vercel.app/rehearse): 가디언과 임계값을 직접 골라 복구 전체를 해 봅니다. 네트워크와 증명 없이 브라우저 안에서 실행됩니다.
- [복구 키트](https://lantern-midnight.vercel.app/kit): 브라우저에서 만드는 연습용 키트입니다. 소유자가 보관하는 거부권 카드와 단어로 적는 가디언 키트, 소리 내어 비교하는 여섯 단어 지문이 있습니다.

저장소에서 (Node 22.12 이상 권장):

```sh
git clone https://github.com/OoJae/lantern && cd lantern
npm ci && npm test        # 모든 단위 테스트, 1분 이내. Compact 도구도 Docker도 필요 없습니다
npm run attack            # 네 가지 가디언 설계를 공격합니다. 셋은 뚫리고 Lantern은 버팁니다
npm run story             # 74단계 복구 전체를 실행하고, 각 결과가 예상과 같은지 확인합니다
```

Compact 0.31.1을 설치했다면 `npm run compile:check`가 모든 컨트랙트를 소스에서 다시 컴파일해, 커밋된 모듈과 바이트 단위로 비교합니다.

Midnight의 공개 테스트 네트워크인 Preprod의 기록은 지갑 없이 확인할 수 있습니다 (Node 24 이상, compact 0.31.1):

```sh
npm ci && npm ci --prefix devnet && bash devnet/compile.sh
LANTERN_NETWORK=preprod npm run devnet:verify                  # 전체 이야기: deployments/preprod.json
LANTERN_NETWORK=preprod node devnet/src/shipped.mjs verify     # 수정 없이 배포한 컨트랙트: deployments/preprod-shipped.json
LANTERN_NETWORK=preprod npm run devnet:verify:v2               # Lantern v2: deployments/preprod-v2.json
```

세 명령 모두 체인 위의 검증 키가 새로 컴파일한 결과와 같은지, 유지보수 권한이 동결되었는지, 기록된 모든 트랜잭션이 기록된 블록에 있는지 확인합니다.

## 무엇이 실제이고, 무엇이 아닌가

- 호스팅된 데모는 브라우저 안의 메모리 원장에서 컴파일된 회로를 실행합니다. 증명은 만들지 않습니다.
- 실제 증명과 실제 DUST 수수료는 로컬 체인과 Preprod 실행에 있습니다. 74단계 전체 이야기는 49개의 트랜잭션으로 두 곳 모두에서 실행되었고, 복구 확정까지 마쳤습니다. 이때의 컨트랙트는 72시간 대신 60초 잠금을 쓰도록 한 줄만 바꾼 버전입니다.
- 한 줄도 바꾸지 않고 배포한 컨트랙트도 Preprod에 있으며, 실제 72시간 잠금이 걸린 복구가 열려 있습니다. 이 복구는 2026년 9월 27일 15:03 UTC 이전에는 확정할 수 없습니다.
- Lantern v2도 별도 컨트랙트로 Preprod에 배포되어 있습니다. 수정 없이 배포한 컨트랙트를 대신하지 않고, 그 옆에 있습니다. v2의 각 규칙을 한 번씩 실행했으며, v2의 최소 대기 기간인 24시간을 기다리지 않았으므로 v2의 복구는 어느 체인에서도 확정하지 않았습니다.
- 메인넷에는 아무것도 배포하지 않았고, 외부 감사도 받지 않았습니다.
- 데모와 이야기에 나오는 인물(하나, 서연 등)은 모두 가상의 인물입니다.

## 한계

- *t*명의 가디언이 공모하면 신원을 가져갈 수 있습니다. 소유자가 얻는 것은 복구가 열린 순간부터의 공개 통지와 최소 72시간, 그리고 그들이 갖지 못한 거부권 카드입니다. 복구 요청에는 만료가 없으므로, 직접 시작하지 않은 복구는 오래되었거나 승인이 하나도 없더라도 거부권 카드로 취소하세요.
- 공모한 가디언은 복구가 확정되기 전까지 소유자처럼 행동할 수도 있습니다. 따로 배포된 DApp은 위원회가 복구 이후의 스냅숏을 봉인할 때까지 옛 비밀값을 받아들이며, 각 스냅숏은 봉인 뒤 24시간 동안 유효합니다.
- 가디언을 교체해도 그 가디언의 조각은 무효가 되지 않습니다. 교체(rotation)는 승인 자격만 없애고 신원 비밀값은 그대로 두므로, 다음 복구가 확정될 때까지는 같은 분배에서 나온 옛 조각 *t*개만 있으면 비밀값을 다시 만들어 소유자처럼 행동할 수 있습니다. 더는 믿을 수 없는 가디언을 끊어 내려면 새 비밀값으로 자신에게 복구한 뒤 새 키트를 나누어 주세요.
- 임계값과 가디언 수는 공개됩니다. 숨겨지는 것은 가디언이 누구인가입니다.
- 복구는 누구나 열 수 있습니다. 새 기기에는 인증에 쓸 비밀값이 없기 때문입니다. 요청 횟수 제한은 v2에서 구현하고 테스트했으며, v2는 수정 없이 배포한 컨트랙트 옆에 별도 컨트랙트로 Preprod에 배포되어 있습니다(그 컨트랙트를 대신하지는 않습니다).

v2 설계와 구현(영어): [docs/v2.md](docs/v2.md). 요청 횟수 제한, 거부권 카드로 거는 긴급 잠금, 등록 때 고르는 대기 기간, 누구인지 드러내지 않는 가디언 점검을 다룹니다. v2는 별도 컨트랙트([`contracts/v2/lantern2.compact`](contracts/v2/lantern2.compact))로 구현하고 테스트했으며(`npm run test:v2`), 수정 없이 배포한 컨트랙트 옆에 따로 Preprod에 배포했습니다. 그 컨트랙트를 대신하지는 않습니다. Preprod에서 v2의 각 규칙을 한 번씩 실행했습니다. 16단계 가운데 12단계는 받아들여지고 4단계는 회로 자체의 assert로 거부되었으며, 트랜잭션은 15개입니다. 이 기록([`deployments/preprod-v2.json`](deployments/preprod-v2.json))은 `LANTERN_NETWORK=preprod npm run devnet:verify:v2`로 지갑 없이 확인할 수 있습니다. Preprod에 수정 없이 배포한 컨트랙트는 동결된 채 바뀌지 않습니다.
